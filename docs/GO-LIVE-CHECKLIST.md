| ชุด | โปรเจกต์ | ใครใช้ |
|---|---|---|
| ชุดจริง | `pms` · `yhhhcrvhkforwsagojho` | ระบบที่จะเปิดใช้จริง · สคริปต์สำรอง/กู้คืน/ตรวจความพร้อม |
| ชุดทดสอบ | `pms-test` · `fxckixlzsfqalqukhuud` | ตอนพัฒนาในเครื่อง · ชุดทดสอบอัตโนมัติ · ทดสอบโหลด |

**ค่าเชื่อมต่ออยู่ที่ไหน**
- `apps/hq/.env.local` · `apps/dealer/.env.local` → **ชุดทดสอบ**
- `.env.production.local` → **ชุดจริง** (สคริปต์ดูแลระบบอ่านจากที่นี่ผ่าน `scripts/lib/targetEnv.mjs`)
- ทุกสคริปต์บอกก่อนทำงานว่ากำลังแตะฐานไหน — อ่านบรรทัด `🎯 ฐานข้อมูลที่จะแตะ:` ก่อนกดทุกครั้ง

> ⚠️ **ห้ามให้สคริปต์ดูแลระบบอ่าน `apps/hq/.env.local`** — ไฟล์นั้นชี้ชุดทดสอบ
> ถ้าพลาด การสำรองข้อมูลจะไปสำรองชุดทดสอบแทนชุดจริงโดยไม่มีอะไรเตือน แล้ววันที่ต้องกู้จริงถึงจะรู้ว่าไฟล์สำรองทั้งกองไม่มีข้อมูลลูกค้าเลย

**เวลาสร้างฐานข้อมูลใหม่ ต้องทำเพิ่ม 1 อย่างที่ไมเกรชันทำให้ไม่ได้**

`supabase config push --project-ref <รหัสโปรเจกต์>` — เปิด hook ที่ยัดสิทธิ์ลงใบผ่านเข้าระบบ
ไม่ทำ = ทุกคนล็อกอินได้แต่เห็นข้อมูลว่างเปล่าทุกหน้า (เจอตอนแยกฐาน ชุดทดสอบตก 45 ข้อ)
ตอนนี้ค่านี้เขียนไว้ใน `supabase/config.toml` แล้ว ไม่ต้องพึ่งความจำใคร

**อีกอย่างที่ไมเกรชันทำให้ไม่ได้: เปิด Send Email Hook: Postgres · public · hook_send_email**
Supabase ระบบจริง → Authentication → Hooks → Send Email Hook → Postgres · public · hook_send_email (ไม่แตะ Customize Access Token hook)
ไม่ทำ = ใบ 0213 ลงแล้วแต่ไม่กันอะไร ใครก็ขอลิงก์ลืมรหัสผ่าน/เลขเข้าระบบไปโดเมนที่เราไม่ได้คุมได้ (19 ต.ค. 69 หลุดมาแล้วรอบหนึ่ง)
ตรวจ: ชุด prod-live ต้องได้ 403 + `auth_email_disabled` จาก /recover และ /otp

## 3. ข้อมูลตั้งต้นที่ต้องมีก่อนเปิดใช้

### 3.1 ข้อมูลบริษัทเบนจามิน (หน้าตั้งค่า › บริษัท)

ข้อมูลนี้ไปโผล่บนใบเสนอราคาที่ตัวแทนส่งให้ลูกค้า กรอกผิด = เอกสารที่ส่งออกไปแล้วผิดตาม

- ✅ ชื่อบริษัท · ที่อยู่ · โทรศัพท์ — ดึงมาจากระบบเดิม (`C:\.claude\file-benjamintomail`)
- ⛔ **เลขประจำตัวผู้เสียภาษี** — ระบบเดิมไม่เคยกรอก ต้องขอจากฝ่ายบัญชี
- ⛔ **อีเมลกลาง** — ระบบเดิมเป็นค่าตัวอย่างที่ติดมากับตัวติดตั้ง (`info@example.com`) ใช้ไม่ได้
- ⛔ **เว็บไซต์** — ระบบเดิมไม่มีช่องนี้
- ⬜ ตรวจว่าชื่อที่กรอกตรงกับชื่อจดทะเบียนจริง (ระบบเดิมเขียนไว้ว่า "เบญจมินทร์ ( BENJAMIN )" ซึ่งไม่ใช่รูปแบบชื่อนิติบุคคล)

### 3.2 ทะเบียนตัวแทนจำหน่าย ⛔

- ⛔ รายชื่อตัวแทนจริง + จังหวัด + ภูมิภาค (ฐานจริงตอนนี้มีรายเดียวคือ DSF ที่ใช้ทดสอบ — ตรวจ 3 ก.ย. 69)
- ⛔ เป้ายอดขายรายปีของแต่ละราย
- ⬜ สร้างบัญชีล็อกอินให้แต่ละราย แล้วส่งรหัสผ่านให้ทางช่องทางที่ปลอดภัย
- ⬜ ให้แต่ละสาขาเข้าไปตั้งค่าเอกสารของตัวเอง (คำนำหน้าเลขที่ใบ · VAT · ข้อความท้ายเอกสาร)

> หมายเหตุ: ระบบออกแบบให้ **1 ตัวแทน = 1 บัญชี** โดยตั้งใจ ไม่ใช่ข้อจำกัดที่ลืมทำ

### 3.3 แคตตาล็อกสินค้าและราคากลาง — ยกเลิก ✅ (16 ต.ค. 69)

- **เอาแม่แบบออกทั้งระบบ** (บอสสั่ง 16 ต.ค. 69) — ไม่ต้องกรอกแม่แบบ/ราคากลางอีก
  สำนักงานใหญ่พิมพ์รายการในใบ HQ เอง (ชื่อ · จำนวน · หน่วย · ต้นทุน) · ดีลเลอร์ตั้ง % บวกตั้งต้นที่ ตั้งค่า › ตั้งค่าใบเสนอราคา
- ตาราง `master_catalog` ในฐานยังอยู่ (ห้าม drop) แต่ไม่มีโค้ดแอปใช้ — ตัวตรวจ `scripts/check-no-catalog.mjs` · API แม่แบบตอบ 410

### 3.4 นโยบายและเป้าหมายของสำนักงานใหญ่ ⛔

- ⛔ เป้ายอดขายรวมทั้งปี — ตอนนี้ตั้งไว้ 260 ล้าน แต่เป้าของตัวแทนรวมกันได้ 55.5 ล้าน ไม่ตรงกัน
- ⬜ อัตราปิดการขายเป้าหมาย · VAT · อายุใบเสนอราคา
- ⬜ เหตุผลที่ปิดการขายไม่สำเร็จ — ตรวจว่าครอบคลุมของจริง
