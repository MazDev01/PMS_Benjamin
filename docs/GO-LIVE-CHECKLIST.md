> ถ้าพลาด การสำรองข้อมูลจะไปสำรองชุดทดสอบแทนชุดจริงโดยไม่มีอะไรเตือน แล้ววันที่ต้องกู้จริงถึงจะรู้ว่าไฟล์สำรองทั้งกองไม่มีข้อมูลลูกค้าเลย

ไม่ทำ = ทุกคนล็อกอินได้แต่เห็นข้อมูลว่างเปล่าทุกหน้า (เจอตอนแยกฐาน ชุดทดสอบตก 45 ข้อ)

## 3. ข้อมูลตั้งต้นที่ต้องมีก่อนเปิดใช้

### 3.1 ข้อมูลบริษัทเบนจามิน (หน้าตั้งค่า › บริษัท)

ข้อมูลนี้ไปโผล่บนใบเสนอราคาที่ตัวแทนส่งให้ลูกค้า กรอกผิด = เอกสารที่ส่งออกไปแล้วผิดตาม

- ✅ ชื่อบริษัท · ที่อยู่ · โทรศัพท์ — ดึงมาจากระบบเดิม (`C:\.claude\file-benjamintomail`)
- ⛔ **เลขประจำตัวผู้เสียภาษี** — ระบบเดิมไม่เคยกรอก ต้องขอจากฝ่ายบัญชี
- ⛔ **อีเมลกลาง** — ระบบเดิมเป็นค่าตัวอย่างที่ติดมากับตัวติดตั้ง (`info@example.com`) ใช้ไม่ได้
- ⛔ **เว็บไซต์** — ระบบเดิมไม่มีช่องนี้
- ⬜ ตรวจว่าชื่อที่กรอกตรงกับชื่อจดทะเบียนจริง (ระบบเดิมเขียนไว้ว่า "เบญจมินทร์ ( BENJAMIN )" ซึ่งไม่ใช่รูปแบบชื่อนิติบุคคล)

### 3.2 ทะเบียนตัวแทนจำหน่าย ⛔

- ⛔ รายชื่อตัวแทนจริง + จังหวัด + ภูมิภาค (ฐานจริงตอนนี้มีรายเดียวคือ DSF ที่ใช้ทดสอบ — ตรวจ 3 ก.ย. 69)
- ⛔ เป้ายอดขายรายปีของแต่ละราย
- ⬜ สร้างบัญชีล็อกอินให้แต่ละราย แล้วส่งรหัสผ่านให้ทางช่องทางที่ปลอดภัย
- ⬜ ให้แต่ละสาขาเข้าไปตั้งค่าเอกสารของตัวเอง (คำนำหน้าเลขที่ใบ · VAT · ข้อความท้ายเอกสาร)

> หมายเหตุ: ระบบออกแบบให้ **1 ตัวแทน = 1 บัญชี** โดยตั้งใจ ไม่ใช่ข้อจำกัดที่ลืมทำ

### 3.3 แคตตาล็อกสินค้าและราคากลาง ⛔ ← เร่งด่วนที่สุด

- ⛔ **ฐานข้อมูลจริงยังไม่มีแม่แบบสักรายการ (0 แถว)** → ตัวแทนออกใบเสนอราคาไม่ได้เลยสักใบ (ตรวจ 3 ก.ย. 69)
  วิธีที่เร็วที่สุด: หน้าตั้งค่า › บริษัท › **ส่งออก (สำรองข้อมูล)** จะได้ไฟล์ Excel ที่มีหัวตารางครบทุกแท็บ
  พิมพ์แม่แบบ/ราคา/รายชื่อตัวแทนลงไป แล้ว **นำเข้า (กู้คืน)** กลับ — เข้าทีเดียวทั้งชุด
- ⛔ แม่แบบย่อยรวม 23 แบบ ยังไม่มีการตั้งราคาแยกรายตัวสักแบบ (ระบบรองรับแล้ว — ไม่ตั้ง = ใช้ราคาแม่แบบหลัก)
- ⬜ ตรวจว่าแม่แบบย่อยของแต่ละแม่แบบตรงกับที่ขายจริง
- ⬜ ตั้งวันที่เริ่มใช้ราคาให้ถูกต้อง

> ⚠️ ราคากลางเป็นตัวตั้งของทุกใบเสนอราคา ผิดที่นี่ = ผิดทั้งเครือ

### 3.4 นโยบายและเป้าหมายของสำนักงานใหญ่ ⛔

- ⛔ เป้ายอดขายรวมทั้งปี — ตอนนี้ตั้งไว้ 260 ล้าน แต่เป้าของตัวแทนรวมกันได้ 55.5 ล้าน ไม่ตรงกัน
- ⬜ อัตราปิดการขายเป้าหมาย · VAT · อายุใบเสนอราคา
- ⬜ เหตุผลที่ปิดการขายไม่สำเร็จ — ตรวจว่าครอบคลุมของจริง

       → คาดว่าบนสำเนาข้อมูลจริงก็พังแบบเดียวกัน: เตรียมแผนลงฐาน+โค้ดติดกันนอกเวลาทำการ และแจ้งดีลเลอร์ไว้ได้เลย (ยืนยันอีกครั้งตอนซ้อมจริง)
5. ผ่านครบ (ลงใบผ่าน · ข้อมูลเท่าเดิม · audit 0 จุด · smoke ตก 0 · smoke-old ตัดสินช่วงเวลาลงแล้ว) แล้วจึงไปข้อ 5 ลงใบบนระบบจริง

ซ้อมตัวสคริปต์แล้ว 15 ต.ค. 69 บนฐานในเครื่องที่ตั้งเป็นใบ 0181 + ข้อมูลแบบระบบจริง: ลง 28 ใบผ่าน · ข้อมูลเท่าเดิม 10 ตาราง · audit 0 จุด · smoke ผ่าน 18 ตก 0

## 5.1 สวิตช์ซ่อนราคาแม่แบบจากดีลเลอร์ (Flow ใบ HQ) ⛔ ยังห้ามเปิด

สวิตช์ `hq_policy.hide_catalog_price` (ใบ 0186) เปิดแล้วดีลเลอร์อ่านราคาแม่แบบไม่ได้ที่ระดับฐานข้อมูล
**ห้ามเปิดในระบบจริงจนกว่า Flow ใบ HQ จะขึ้นระบบและใช้งานได้จริง** — เปิดก่อน = ดีลเลอร์ออกใบเสนอราคาไม่ได้ทั้งเครือ
โดยไม่มีข้อความ error (เห็นแค่รายการแม่แบบว่าง)

ก่อนเปิดสวิตช์ในระบบจริง ต้องครบ **ทั้งสองข้อ** — ข้อใดข้อหนึ่งไม่พอ:

- [ ] `npm run preflight` ข้อ "สวิตช์ซ่อนราคาแม่แบบ" ผ่าน
      ⚠️ **preflight ผ่านไม่ได้แปลว่าพร้อม** — มันตรวจแค่ว่ามีใบ HQ ที่ส่งถึงดีลเลอร์แล้วอย่างน้อย 1 ใบ
      ใบทดสอบใบเดียวก็ทำให้ผ่านได้ มีไว้กัน "เปิดทั้งที่ยังไม่มีอะไรเลย" เท่านั้น
- [ ] ผลชุดทดสอบใบผ่านจริงผ่านครบ: `npx playwright test --project=price-switch`
      (ยิงด้วยใบผ่านของดีลเลอร์จริงทั้ง REST ตรงและผ่าน `/api/v1` — ดีลเลอร์ต้องอ่านราคาไม่ได้ทั้งสองทาง HQ ยังอ่านได้)
- [ ] หน้าจอของดีลเลอร์อ่านแม่แบบผ่าน `master_catalog_public` แล้ว และออกใบจากใบ HQ ได้จริงครบวงจร
      (ส่งคำขอ → รับใบ HQ → ทำใบให้ลูกค้า → ปิดการขาย) บนระบบจริงอย่างน้อย 1 งานจริง ไม่ใช่งานทดสอบ
      จดหลักฐานของงานจริงนั้นไว้ที่นี่ก่อนเปิดสวิตช์ — ช่องไหนว่าง = ยังเปิดไม่ได้:

      | รายการ | ค่า |
      |---|---|
      | ดีลเลอร์นำร่อง (รหัส · ชื่อ) | ____________ |
      | เลขคำขอใบเสนอราคา (RQ-…) | ____________ |
      | เลขใบ HQ (HQ-…-V…) | ____________ |
      | เลขใบเสนอราคาลูกค้า (Q-…) | ____________ |
      | วันที่ปิดการขาย · ผู้ตรวจ | ____________ |

**ปิดสวิตช์ฉุกเฉิน** (ดีลเลอร์แจ้งว่ารายการแม่แบบว่าง): `update hq_policy set hide_catalog_price = false;`

**พิสูจน์ว่าชุดทดสอบปิดสวิตช์คืนแม้ตกกลางทาง** (ฐานทดสอบเท่านั้น):
`PMS_FORCE_FAIL_PRICE_SWITCH=1 npx playwright test --project=price-switch --no-deps` → ชุดต้องตก
แล้วตรวจ `select hide_catalog_price from hq_policy` ต้องได้ `false`

## 6. ก่อนส่งมอบให้ผู้ใช้ ⬜

- ⬜ ทดลองใช้จริงกับตัวแทน 1–2 ราย ตั้งแต่สร้างลูกค้าเป้าหมายจนปิดการขาย

- ⬜ ตกลงว่าใครเป็นคนดูแลระบบหลังส่งมอบ
